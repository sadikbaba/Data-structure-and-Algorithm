# Phase 1: Problem-Solving and Big-O

This is where the DSA journey starts.

The goal is simple: learn how to approach a problem before jumping into code, then learn how to judge whether a solution is efficient.

## What I'm Learning

### Problem-Solving Process

For every unfamiliar problem, I will practice this sequence:

1. Understand the problem
2. Identify the inputs and outputs
3. Work through examples
4. Check edge cases
5. Start with a brute-force solution
6. Find the bottleneck
7. Improve the solution
8. Analyze time and space complexity
9. Test the result

### Big-O

I will learn to reason about:

`O(1)`
`O(log n)`
`O(n)`
`O(n log n)`
`O(n²)`
`O(2ⁿ)`
`O(n!)`

The focus is not memorizing these names.

The focus is being able to look at code and explain **why** it has a particular complexity.

## Practice

Practice will include:

* Analyzing short pieces of code
* Finding time and space complexity
* Breaking unfamiliar problems into smaller steps
* Writing the brute-force approach first
* Finding the bottleneck
* Improving the solution
* Testing edge cases
* Using selected LeetCode problems when they fit the topic

## The Rule

I don't move to an optimized solution just because I know it.

I should be able to explain:

> What would the simple solution do?
>
> What makes it slow?
>
> Where is the bottleneck?
>
> What can be improved?
>
> Why is the new approach better?

## Finish Line

I am ready to leave this phase when I can:

* Analyze unfamiliar code and determine its complexity
* Explain why the complexity has that cost
* Approach a new problem systematically
* Identify the bottleneck before optimizing
* Explain my reasoning without relying on notes
